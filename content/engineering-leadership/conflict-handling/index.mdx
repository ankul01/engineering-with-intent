# Conflict Handling

Conflict is inevitable in engineering teams. How you handle it determines whether it becomes destructive or leads to better outcomes. This guide covers managing disagreements constructively.

### Healthy vs Unhealthy Conflict

| Healthy Conflict | Unhealthy Conflict |
|-----------------|-------------------|
| Focus on ideas | Focus on people |
| Seeks understanding | Seeks to win |
| Data-driven | Emotion-driven |
| Leads to better decisions | Damages relationships |
| Resolved constructively | Festers or escalates |

## Conflict Resolution Framework

### The 5-Step Process

```
1. Acknowledge
   "I can see we have different views on this."

2. Understand
   "Help me understand your perspective."
   
3. Find Common Ground
   "We both want [shared goal]."

4. Generate Options
   "What are the possible ways forward?"

5. Agree on Path Forward
   "Let's try X and revisit if needed."
```

### Active Listening

```
┌─────────────────────────────────────────────────────────────┐
│                 Active Listening                             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  DO:                                                         │

│  ├── Ask clarifying questions                               │
│  ├── Paraphrase to confirm understanding                    │

│                                                              │
```

## Technical Disagreements

### Decision-Making Framework

```
For technical decisions:

1. Define the decision clearly
   "We need to decide between X and Y for [purpose]"

2. List criteria for success
   "A good solution must..."

3. Gather data
   - Benchmarks, prototypes, research

4. Present options objectively
   - Pros/cons of each approach

5. Make the call
   - Decision-maker decides (Tech Lead, Architect)
   - Document reasoning

6. Disagree and commit
   - Once decided, everyone supports
```

### RFC/ADR Process

```
RFC (Request for Comments):
┌─────────────────────────────────────────────────────────────┐
│  Title: [Decision Title]                                    │
│  Author: [Name]                                              │
│  Status: Draft → Review → Approved/Rejected                 │
│                                                              │
│  Context:                                                    │
│  [Why this decision needs to be made]                       │
│                                                              │
│  Options Considered:                                         │
│  1. [Option A] - Pros/Cons                                  │
│  2. [Option B] - Pros/Cons                                  │
│                                                              │
│  Decision:                                                   │
│  [What we chose and why]                                    │
│                                                              │
│  Consequences:                                               │
│  [What this means going forward]                            │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### When to Escalate

| Escalate when: | Don't escalate when: |
|----------------|---------------------|
| Impact is significant | It's a minor preference |
| No consensus after good faith effort | Haven't tried to resolve |
| Decision is time-sensitive | Can wait for more data |
| Relates to cross-team impact | Local to one team |

## Interpersonal Conflicts

### One-on-One Mediation

```
Step 1: Meet with each party separately
├── Understand their perspective
├── Identify core concerns
├── Build trust
└── Gauge willingness to resolve

Step 2: Joint meeting (if appropriate)
├── Set ground rules
├── Each shares perspective (no interruptions)
├── Focus on behaviors, not personalities
└── Work toward shared understanding

Step 3: Agreement
├── What will each person do differently?
├── How will success be measured?
└── When will we check in?

Step 4: Follow up
├── Monitor the situation
├── Recognize improvements
└── Address any regression
```

### Difficult Conversation Framework

```
1. State the problem
   "I've noticed [specific behavior]"

2. Describe impact
   "The impact is [concrete consequence]"

3. Invite their perspective
   "Help me understand what's happening"

4. Problem-solve together
   "What could we do differently?"

5. Agree on next steps
   "So we're agreeing to [specific actions]"
```

### Managing Your Own Emotions

| Situation | Strategy |
|-----------|----------|
| Feeling defensive | Pause, breathe, ask clarifying question |
| Getting angry | Take a break if needed |
| Shutting down | Name the emotion, re-engage |
| Taking it personally | Separate behavior from intent |

## Team Conflicts

### Common Team Dynamics Issues

| Issue | Signs | Approach |
|-------|-------|----------|
| **Blame culture** | Finger-pointing, CYA behavior | Blameless retros, psychological safety |
| **Silos** | Information hoarding | Cross-team projects, shared goals |
| **Passive-aggressive** | Indirect communication | Address directly, model directness |
| **Dominance** | One voice dominates | Structured discussions, inclusive facilitation |

### Facilitating Healthy Debate

```
Techniques for inclusive discussion:

1. Round-robin
   - Everyone shares before discussion

2. Written input first
   - Silent brainstorming, then discuss

3. Devil's advocate
   - Assign someone to argue against

4. Parking lot
   - Capture tangents, address later

5. Time-boxing
   - Prevent endless debate
```

## Cross-Team Conflicts

### Common Sources

| Source | Example |
|--------|---------|
| **Competing priorities** | Team A needs Team B's help, Team B is slammed |
| **Unclear ownership** | Who owns this shared service? |
| **Blame shifting** | "It's not our bug, it's theirs" |
| **Resource competition** | Both teams want same headcount |

### Resolution Approaches

```
1. Clarify ownership
   - RACI for shared areas
   - Documented boundaries

2. Escalate appropriately
   - Bring to shared manager
   - Present both sides fairly

3. Seek win-win
   - What would help both teams?
   - Creative solutions

4. Commit to agreements
   - Document decisions
   - Follow through
```

## Prevention

### Building a Healthy Conflict Culture

| Practice | How |
|----------|-----|
| **Psychological safety** | Model vulnerability, no punishment for speaking up |
| **Clear decision rights** | Everyone knows who decides what |
| **Direct communication** | Encourage addressing issues early |
| **Regular retros** | Surface issues before they fester |
| **Celebrate disagreement** | "I'm glad we talked this through" |

### Early Warning Signs

```
Watch for:
├── Reduced participation in discussions
├── Increase in side conversations
├── People avoiding each other
├── Passive-aggressive comments
├── Escalation of small issues
└── Morale dip
```

## Interview Quick Reference

### Common Questions

1. **"Tell me about a conflict you resolved"**
   - Use STAR format
   - Show empathy for all sides
   - Focus on process, not just outcome
   - Highlight learning

2. **"How do you handle technical disagreements?"**
   - Data over opinions
   - Clear decision-making process
   - Disagree and commit
   - Document decisions

3. **"What do you do when two team members clash?"**
   - Listen to both sides
   - Find common ground
   - Facilitate conversation
   - Set clear expectations
   - Follow up

### Conflict Handling Checklist

- [ ] Both sides heard?
- [ ] Underlying interests understood?
- [ ] Common ground identified?
- [ ] Options explored?
- [ ] Decision made and documented?
- [ ] Follow-up planned?
- [ ] Relationship preserved?
